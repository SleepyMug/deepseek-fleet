# TODOs

- **Keep the helper out of the model's reach.** The helper runs on the image's `/usr/local/bin/node` from `/opt`, and its sockets sit in the container's `/tmp` (dsh-ssh hard-codes `mkdtemp('/tmp/dsh-ssh-')`), all writable by the model: `pkill node` ends the session's running commands until the next use reconnects, a routine `rm -rf /tmp/*` breaks later spawns, and replacing that Node breaks the helper until the container is recreated. Mount a read-only folder holding the helper and its own Node, and move the socket root to a dedicated mount such as `/run/fleet`, ideally through an upstream option rather than a `node --import` shim that wraps `mkdtemp`. `/tmp` could then leave the RAM-backed runtime directory for disk, where one large build cannot fill the desktop session's tmpfs, and files a non-root user creates there no longer block the host's clean-up.
- **Chat file links.** session-controller serves `/api/file`, the chat's images and file links, through `ctx.fs` outside any session, so the world refuses them. Serving them needs the request's session, to read from its container.
- **Stop idle containers.** The web app never releases a session once it is opened, and each open container keeps a helper of about 80 MB, so close a session's world after a stretch with nothing running (the same running-work check dsh uses before archiving); its teardown stops the container, and the next step starts it again. Processes the model left running outside a background job would die with it.
- **Forks and containers.** A fork gets a fresh container and a notice that earlier installs are gone; it could instead start from a copy of its source's container (`docker commit`), so installed tools carry over.
- **Fleet as one installable product.** Today each piece is added to the fleet profile by hand (`dsh plugin --profile fleet add` for profile-fleet, fleet-box and fleet-setup). A top-level `fleet` package, installed directly, could bring dsh and those packages with it, and `fleet-setup` could then also create and update the fleet profile, so setting up a machine is one command beside the image and sign-in parts.
