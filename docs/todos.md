# TODOs

- **Spill files.** Oversized results keep only what fits: bash output keeps its tail and reports the full output as unavailable, and spill-policy is disabled, so large tool results stay inline. Both spill to host files the model cannot open from its container. The helper could write spills inside the container instead and report their container paths, so both `cat` and `read` find them.
- **Chat file links.** session-controller serves `/api/file`, the chat's images and file links, through `ctx.fs` outside any session, so the world refuses them. Serving them needs the request's session, to read from its container.
- **Stop idle containers.** The web app never releases a session once it is opened, and each open container keeps a helper process, so close a session's world after a stretch with nothing running (the same running-work check dsh uses before archiving); its teardown stops the container, and the next step starts it again. Processes the model left running outside a background job would die with it.
- **Helper updates keep containers.** The helper is built into the session image, so any change to its sources, even a comment, gives a new image tag, and every session's container is recreated on its next use, losing installed packages and `/tmp`. The helper could live outside the image instead, mounted read-only at a fixed path and reporting its version in `hello`, so an update restarts only the helpers.
- **Forks and containers.** A fork gets a fresh container and a notice that earlier installs are gone; it could instead start from a copy of its source's container (`docker commit`), so installed tools carry over.
- **Fleet as one installable product.** Today each piece is added to the fleet profile by hand (`dsh plugin --profile fleet add` for profile-fleet, fleet-box and fleet-setup). A top-level `fleet` package, installed directly, could bring dsh and those packages with it, and `fleet-setup` could then also create and update the fleet profile, so setting up a machine is one command beside the image and sign-in parts.
- **More of the subprocess seam.** The container world serves what bash needs: collected output, and stdin ignored or given as data. Raw pipes, the fd 7 control channel (PTC) and terminals are refused, so fs-search, LSP, PTC and the sidebar terminal stay off; they would need per-stream flow control between host and helper.
